# Shared ComponentErrorOverlay = port extension's CURRENT superset, not the reference branch's older version

## Rationale

HYP-648 ticket references pre-HYP-561 branch worktree-HYP-shared-error-overlays whose ComponentErrorOverlay is the OLD/simpler shape (componentName/onConfigureAI/onCreateSample, PROPS_CACHE LRU). But current main's extension (inline in PreviewPanelApp.tsx) is a strict SUPERSET: componentPath+errorSeq shape, unsatisfiedProps + computeAttentionProps (feature #210/HYP-453), errorBoundary:createSample/configureAIKey/getPropsSchema messages, errorBoundary:propsSchema response. Blindly porting the reference would REGRESS the extension. Decision: the shared ComponentErrorOverlay is the extension's current component lifted into shared/components/overlays/, re-tokenized --vscode-* -> --overlay-*, keeping ALL current props/behavior. Same for PropsForm: main's decomposed PropsForm/ directory (SimplePropInfo, getGenerateAllAvailability, canGenerateSomeValue) is NEWER than the reference's single 1193-line PropsForm.tsx — move the decomposed dir to shared (re-tokenized), not the reference file. SaaS becomes a NEW consumer; extension switches to importing from @shared/components/overlays. Both CSS files already define the full --overlay-* set; a few extra --vscode tokens used by PropsForm styles (textCodeBlock-background, list-activeSelectionBackground, focusBorder, disabledForeground, badge-background, button-secondaryBackground) get mapped to existing --overlay-* or added as new tokens to theme.ts + both CSS + theme.test.ts. HYP-649 recovery: extension ALREADY recovers via hypercanvas:componentRenderSucceeded + _ComponentSuccessSignal + componentDidUpdate-reset in generated boundary; the ticket's retryRender/key-remount is an ADD that hardens the path (force remount on retry) without ripping out the working reset.
