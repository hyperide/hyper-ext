# Preview Routing Design

## Status: DECIDED — App Shell default, Isolated opt-in

---

## Terminology

- **app wrap** — the invisible infrastructure context of the user's app: CSS imports, React providers
  (QueryClient, ThemeProvider, auth context, etc.). Components need this to render correctly.

- **app chrome** — the visible navigation UI of the app: navbar, sidebar, header, footer.
  Not part of the component being previewed. Undesirable in preview.

- **synthetic wrap** — a user- or AI-generated `.hyperide/preview.tsx` that reproduces the
  app wrap (providers + CSS imports) without the chrome. This is what Isolated mode uses.
  Unlike App Shell's inherited wrap, synthetic wrap may drift from the real app over time.

**App Shell mode** inherits the real app wrap automatically. Whether chrome appears depends
on how the framework's route structure is set up:

- Next.js App Router with blank segment layout → wrap inherited, chrome hidden ✓
- Vite JSX router (`<Routes>`) → wrap inherited, chrome visible (expected — see chrome detection)

**Isolated mode** uses synthetic wrap from `.hyperide/preview.tsx`. No chrome by design.

---

## TL;DR

The preview iframe loads `/test-preview` from the user's dev server. The dev server must
serve something at that path that renders `<PreviewRoot />` — a component that reads
`?component=` from the URL and renders the matching component from the registry.

**Two modes depending on the presence of `.hyperide/preview.tsx`:**

- **Without config (zero-config)** → route file generated inside the user's project.
  CSS and providers are inherited from the app shell. May include app chrome in preview.

- **With `.hyperide/preview.tsx`** → Tier 1 (Vite/Parcel) or Tier 2 (Webpack):
  proxy does a script swap or entry patch. Isolated preview without chrome.
  Providers and CSS come from the wrapper config.

---

## Architecture

### App Shell Mode (zero-config, default)

Generate a route file inside the user's project following framework conventions.
The proxy does not touch HTML — it simply proxies `/test-preview`.

```
Dev server knows about /test-preview → serves the page →
page renders <PreviewRoot /> inside the app shell →
CSS and providers are inherited automatically
```

**Works for**: Next.js (App Router, Pages), Remix, Vite SPA with file-based routing
(react-router v7, TanStack Router).

**Problem**: SPA with manual JSX router (`<Routes>`) requires patching the router config.
App chrome (navbar, sidebar) may appear in preview — solved by generating a blank layout file.

---

### Isolated Mode (with wrapper config)

When `.hyperide/preview.tsx` exists, switch to isolated rendering.

**Tier 1 (Vite, Parcel)**:
The proxy intercepts the HTML response and replaces the `<script>` tag:

```html
<!-- original -->
<script type="module" src="/src/main.tsx"></script>

<!-- after swap -->
<script type="module" src="/src/__canvas_preview__.tsx"></script>
```

Vite and Parcel serve any `.tsx` file on demand — `__canvas_preview__.tsx` loads
directly as a standalone entry with `createRoot`, importing the wrapper from config.

**Tier 2 (Webpack, CRA)**:
Webpack does not serve raw files — the entry point is baked into `webpack.config.js`.
Instead of script swap, patch the entry file via AST (`recast`, preserves formatting):

```tsx
// src/index.tsx — after patch
import React from 'react';
import './index.css'; // static imports stay, always execute
import { queryClient } from './lib/query';

if (new URLSearchParams(location.search).get('__preview')) {
  /* @hyperide-managed */
  import('./__canvas_preview__');
} else {
  /* @hyperide-managed */
  ReactDOM.createRoot(document.getElementById('root')!).render(<App />);
} /* @hyperide-managed */
```

On deactivation — strip all lines tagged with `@hyperide-managed`.

### Wrapper Config `.hyperide/preview.tsx`

```tsx
// .hyperide/preview.tsx — written by user or AI-generated
import './src/index.css';
import { QueryClientProvider, queryClient } from './src/lib/query';
import { ThemeProvider } from './src/theme';

export function PreviewWrapper({ children }: { children: React.ReactNode }) {
  return (
    <QueryClientProvider client={queryClient}>
      <ThemeProvider>{children}</ThemeProvider>
    </QueryClientProvider>
  );
}
```

In Isolated mode, `__canvas_preview__.tsx` imports `PreviewWrapper` and wraps the
component. The user explicitly specifies only the providers they need — no guessing.

**When it's created**: manually by the user, or AI-generated by analyzing `main.tsx`
(reads providers from `render()` and CSS imports — a bounded, well-defined task for AI).

**Notification**: on first preview render, detect `<nav>`, `<header>`, `<aside>` in the
DOM. If found — show once: "Preview includes app layout. Configure a wrapper to isolate
components." with an AI generation button.

---

### `__canvas_preview__.tsx` in Each Mode

**App Shell mode** — component only, no `createRoot`:

```tsx
// src/__canvas_preview__.tsx — @hyperide-managed
export function PreviewRoot() {
  const params = new URLSearchParams(window.location.search);
  const componentPath = params.get('component');
  // ... render from registry
}
```

**Isolated mode** — standalone entry with `createRoot` and wrapper:

```tsx
// src/__canvas_preview__.tsx — @hyperide-managed
import { PreviewWrapper } from '../.hyperide/preview';

function PreviewRoot() {
  const params = new URLSearchParams(window.location.search);
  // ...
}

createRoot(document.getElementById('root')!).render(
  <PreviewWrapper>
    <PreviewRoot />
  </PreviewWrapper>,
);
```

## Framework Routing Table

| Bundler / Framework               | Without config (App Shell)                       | With `.hyperide/preview.tsx` (Isolated) |
| --------------------------------- | ------------------------------------------------ | --------------------------------------- |
| Vite + Remix v2                   | Route file: `app/routes/test-preview.tsx`        | Tier 1: proxy script swap               |
| Vite + react-router v7 / TanStack | Route file in routing directory                  | Tier 1: proxy script swap               |
| Vite + react-router v6 (JSX)      | Route file + AST router patch                    | Tier 1: proxy script swap               |
| Parcel                            | Route file + AST router patch                    | Tier 1: proxy script swap               |
| Webpack / CRA                     | Route file + AST router patch                    | Tier 2: AST entry patch                 |
| Next.js App Router                | `app/test-preview/page.tsx` + blank `layout.tsx` | Tier 3: same, wrapper imported in route |
| Next.js Pages Router              | `pages/test-preview.tsx`                         | Tier 3: same, wrapper imported in route |

Next.js is always App Shell mode — it doesn't serve arbitrary `.tsx` files, and
file-based routing solves the problem more cleanly than any proxy magic.

**Framework detection (deterministic, no AI)**:

```
app/layout.tsx exists             → Next.js App Router
pages/_app.tsx exists             → Next.js Pages Router
app/routes/ exists                → Remix v2
react-router in deps + vite.config.ts → Vite SPA
webpack.config.js exists          → Webpack
<script src="..."> in index.html  → Parcel
```

Checked in order, first match wins. If none match — show an error asking the user to
configure the preview route manually.

## Problems, Ranked by Priority

### P0 — Block basic functionality

**[P0-1] App chrome in preview (Next.js, Remix)**

Root `layout.tsx` (App Router) and `root.tsx` (Remix) wrap every page — navbar, sidebar,
and footer end up inside the preview.

_Solution_: generate a blank `app/test-preview/layout.tsx` alongside `page.tsx`:

```tsx
// app/test-preview/layout.tsx — @hyperide-managed
export default function PreviewLayout({ children }: { children: React.ReactNode }) {
  return <>{children}</>;
}
```

In Next.js App Router, a nested layout overrides the visual part of the parent layout,
but providers from root `layout.tsx` **are still inherited** — they run regardless of
the visual structure. CSS is also inherited. Chrome removed, providers intact.

Remix: same via outlet routing.

**[P0-2] Vite SPA with JSX router — router config AST patch**

With the `<Routes>` pattern there is no file-based routing — we need to inject
`<Route path="/test-preview" element={<PreviewPage />} />` into the JSX route tree.

This is the same invasiveness we criticized in Tier 2. The difference: we're not
changing app logic, only adding one route. AST via recast, tagged `@hyperide-managed`,
auto-rollback on deactivation.

Problems:

- Router config can live in `App.tsx`, `main.tsx`, `router.tsx`, or a separate file
- `<Routes>` may be nested inside a layout route with its own providers
- ESLint may complain about the modified file

_Solution_: if wrapper config exists — skip router patching entirely and go Tier 1.
Tier 1 makes the SPA router irrelevant — `__canvas_preview__.tsx` becomes its own entry.
AST router patch is only done in App Shell mode without wrapper.

Fallback if router not found: show instructions for adding the route manually.

---

### P1 — Significantly degrade UX

**[P1-1] Providers scoped to a route subset**

Common pattern: `<AuthProvider>` or `<ThemeProvider>` wraps only `/dashboard/**` but
not `/login` or `/test-preview`. Our route is added at the top level — without those
providers. Components using `useTheme()`, `useAuth()` crash.

_Solution_: wrapper config only. There is no way to automatically determine which
providers a given component needs. AI generates the wrapper by analyzing the component
tree and its provider dependencies — a bounded task. Without wrapper — show a clear
error ("component crashed — may need providers, configure wrapper").

**[P1-2] Webpack Tier 2 — git dirty, lint failures**

Entry file is modified — `git status` shows changes the user didn't make.
ESLint / Prettier / pre-commit hooks may fail.

_Partial solution_:

- Add `/* eslint-disable-next-line */` on injected lines only
- Document that the file will be dirty while HyperIDE is active
- Auto-revert on deactivation

No complete solution — this is the cost of Tier 2. Acceptable because Tier 2 is only
used with wrapper config, meaning it's a deliberate opt-in for isolated preview.

**[P1-3] Switching between modes**

If the user creates `.hyperide/preview.tsx` after App Shell mode is already active —
route files must be deleted and the switch to Tier 1/2 must happen. If the wrapper is
deleted — switch back to App Shell and recreate route files.

_Solution_: FSWatch on `.hyperide/preview.tsx`. On change — reconfigure preview mode,
clean up old files, generate new ones.

---

### P2 — Medium severity, solvable

**[P2-1] Vite base config**

`base: '/app/'` in `vite.config.ts` — all script src attributes have a prefix:
`<script src="/app/src/main.tsx">`. A regex without the base will match nothing.

_Solution_: read `vite.config.ts` at PreviewProxy startup (static analysis or sandboxed
eval). Use the detected base when searching and replacing script src.

**[P2-2] Multiple `<script type="module">` in HTML**

Vite injects `/@vite/client`, `@react-refresh` — also module scripts. Can't blindly
replace the first one found.

_Solution_: filter out scripts whose src starts with `/@`, `/@id/`, or `https://`.
The remaining one is the user's entry. If 0 or 2+ remain after filtering — log a
warning and fall back to App Shell mode.

**[P2-3] Vite plugins transform HTML**

`vite-plugin-html` and similar plugins may transform the script tag before the proxy
sees it.

_Solution_: the regex is flexible enough (match `type="module"` + `src="` pattern,
don't require exact attribute ordering). On script swap failure — detect, log, fall
back to App Shell mode.

**[P2-4] Next.js: `window` in SSR context**

`window.location.search` is unavailable during SSR pre-rendering, even with `'use client'`.

_Solution_: in the generated Next.js `page.tsx`, use `useSearchParams()` from
`next/navigation` (SSR-safe). Requires `<Suspense>` wrapper in App Router:

```tsx
'use client';
import { useSearchParams } from 'next/navigation';
import { Suspense } from 'react';

function PreviewContent() {
  const params = useSearchParams();
  const componentPath = params.get('component');
  // ...
}

export default function TestPreviewPage() {
  return (
    <Suspense>
      <PreviewContent />
    </Suspense>
  );
}
```

**[P2-5] First run — gap before route is ready**

PreviewFileManager writes the route file → dev server FSWatch picks it up → small gap
(50–200ms) → if iframe already opened → 404.

_Solution_: proxy retries on 404 for `/test-preview` with backoff (5 attempts, 200ms
interval). Shows "starting preview..." while waiting.

**[P2-6] Reactive URL params in PreviewRoot**

`window.location.search` is read once on render. When `?component=` changes via
`iframe.src` — a navigation happens → full page reload → fresh render reads the new URL.
This is fine for the current architecture.

Problem only arises if we want instant switch without reload (component already in
registry, only URL param changes). In that case a `popstate` listener or postMessage is
needed.

_Solution for instant switch_: `PreviewRoot` listens to
`window.addEventListener('message')` from the parent frame with
`{ type: 'switchComponent', path: '...' }` and updates state without navigation.
Extension sends postMessage instead of changing `iframe.src`.

---

### P3 — Low priority, edge cases

**[P3-1] Wrapper file goes stale**

User adds a new provider to the app — it's not in the wrapper — components crash again.

_Solution_: on preview crash — offer "Regenerate wrapper". AI reads the current
`main.tsx` and updates `.hyperide/preview.tsx`.

**[P3-2] TypeScript strict mode in generated files**

Generated `__canvas_preview__.tsx` with a dynamic component registry may fail strict
typechecking.

_Solution_: add `// @ts-nocheck` at the top of generated files. They are tooling
artifacts, not user code — they should not be typechecked.

**[P3-3] `/test-preview` route already exists in the user's project**

Unlikely, but if the route exists we would overwrite it.

_Solution_: check before writing. If the file exists and does not contain
`@hyperide-managed` — warn the user and do not overwrite.

**[P3-4] Monorepo root detection**

In Turborepo / Nx, the right package (`apps/web/`) must be found, not the repo root.

_Solution_: walk up the directory tree from the current file looking for a `package.json`
with a `dev` script.

## Why Tier 1/2 Without Wrapper Don't Work

Tier 1 (script swap) and Tier 2 (entry patch) **without a wrapper config** share one
fatal flaw: `__canvas_preview__.tsx` renders the component without CSS and without providers.

- **CSS**: `main.tsx` imports `./index.css`, Tailwind directives, globals. Replacing
  the entry with `__canvas_preview__.tsx` drops all of it. Preview is unstyled.
- **Providers**: `useNavigate()`, `useQuery()`, `useTheme()`, `useSelector()` — all
  crash without the Provider wrappers that lived in the original `render()` call.
  These are exceptions thrown during render, not recoverable render errors.

Reproducing this automatically in a generated file is impossible in the general case.
Every project has a unique provider stack.

**With a wrapper config**, both problems disappear: CSS and providers are explicitly
declared, and Tier 1/2 work correctly.

## Implementation Changes

### Extension (`hypercanvas-preview`)

**`PreviewProxy`**:

- App Shell mode: pass-through + inject scripts. No HTML modification.
- Isolated mode: replace `<script type="module" src="...">` in HTML response.
- Reads `vite.config.ts` on startup to detect `base`.
- FSWatch on `.hyperide/preview.tsx` — switches mode on change.

**`PreviewFileManager`**:

- `ensurePreviewFiles()` — determines mode (App Shell vs Isolated) based on wrapper
  presence, generates the appropriate files.
- `generateRouteFile()` — framework-specific route file.
- `generateBlankLayout()` — empty layout for Next.js / Remix (strips chrome).
- `patchRouterConfig()` — AST patch for Vite SPA JSX router (App Shell mode only,
  no wrapper).
- `generateStandaloneEntry()` — `__canvas_preview__.tsx` with `createRoot` + wrapper
  (Isolated mode).
- `generatePreviewComponent()` — `__canvas_preview__.tsx` without `createRoot`
  (App Shell mode).

**`extension.ts`** — on `currentComponent` change:

1. `ensureSample()` — AI-generates `SampleDefault`
2. `previewFileManager.ensurePreviewFiles()` — idempotent, generates required files
3. URL update or postMessage — no `refresh()` hard reload

### SaaS (`hyper-canvas-draft`)

- `client/main.tsx` — remove `isPreviewPath` check and `__canvas_preview__` import.
- `client/CanvasPreviewEntry.tsx` — delete (dead code).
- `server/routes/generatePreview.ts` — remove HTTP endpoint, call
  `previewFileManager.ensureComponent()` directly from the WebSocket handler.
- `client/components/IframeCanvas.tsx` — remove `POST /api/generate-preview` calls.
- `server/proxy/project-preview.ts` — add Tier 1 HTML rewrite for containers without
  `.hyperide/preview.tsx`, pass-through for those with wrapper.

## Discarded Approaches

| Approach                                | Idea                                                       | Why rejected                                                  |
| --------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------- |
| Worktree + rsync                        | Mirror project with swapped entry, run separate dev server | 100–500ms latency per change, two dev servers, symlink issues |
| Vite plugin                             | Intercept Vite module resolution                           | Vite-only, requires user config change, high complexity       |
| App Shell only (no Isolated mode)       | Route file always, no wrapper                              | Chrome leaks, JSX router patch unavoidable for SPA            |
| Isolated only (no App Shell)            | Script swap / entry patch always                           | No CSS, no providers without wrapper — crash                  |
| **App Shell default + Isolated opt-in** | **Hybrid**                                                 | **Adopted**                                                   |

## Migration Guide

Current state: `__canvas_preview__.tsx` is generated but never loaded. The proxy
rewrites `/test-preview` to `/`, which serves the user's app. Preview is broken.

Each step below is independently shippable and verifiable.

---

### Step 1 — App Shell mode for file-based frameworks (Extension)

**Target**: Next.js App Router, Next.js Pages Router, Remix. No router patching needed —
these frameworks auto-discover route files.

**What to do**:

1. `generator.ts` — change `generatePreviewContent()` to produce a component only.
   Remove `createRoot`, remove `import './index.css'`. Add `export function PreviewRoot`.

2. `PreviewFileManager` — add `generateRouteFile(framework)`. For each framework write
   the appropriate file (see Framework Routing Table). Add `generateBlankLayout()` for
   Next.js App Router.

3. `PreviewFileManager.ensurePreviewFiles()` — call `generateRouteFile()` after
   `ensureComponent()`. Idempotent — skip if `@hyperide-managed` file already exists.

4. `PreviewProxy` — stop rewriting `/test-preview` to `/`. Pass through as-is.
   Keep script injection (interaction, error, console).

5. `extension.ts` — remove `refresh()` call after `ensureComponent()`. Update iframe
   URL via `?component=` param change only.

6. Both generated files tagged `@hyperide-managed`, added to `.gitignore`.

**Verification**: open a Next.js or Remix project, select a component in HyperIDE,
confirm preview renders the component (not the user's app homepage).

---

### Step 2 — App Shell mode for Vite SPA (Extension)

**Target**: Vite + react-router v7 / TanStack Router (file-based). No JSX patching needed.

**What to do**:

1. Extend `generateRouteFile()` to detect file-based routing conventions
   (react-router v7: `app/routes/`, TanStack: `src/routes/`). Write the file there.

2. For react-router v6 (JSX `<Routes>`): implement `patchRouterConfig()` via AST.
   Find the `<Routes>` element, inject `<Route path="/test-preview" element={...} />`.
   Tag injected node with `@hyperide-managed` comment. Revert on deactivation.

**Verification**: open `react-vite-tw4-twitter`, select a component, confirm preview works.

---

### Step 3 — Chrome detection and notification (Extension)

**What to do**:

After the preview iframe loads, inject a small script via `PreviewProxy` that checks
the DOM for `<nav>`, `<header>`, `<aside>` elements outside the preview root. If found,
sends a `postMessage` to the parent. `PreviewPanel` receives it and shows a one-time
notification in the VSCode UI: "Preview includes app layout. Configure a wrapper to
isolate components." with a "Generate wrapper" button.

"Generate wrapper" triggers AI analysis of `main.tsx`: extracts providers from
`render()` call, CSS imports — writes `.hyperide/preview.tsx`.

Store notification dismissal in workspace state so it doesn't repeat.

---

### Step 4 — Isolated mode (Extension, Tier 1 for Vite/Parcel)

**Target**: users who have created `.hyperide/preview.tsx`.

**What to do**:

1. `PreviewProxy` — add FSWatch on `.hyperide/preview.tsx`. When file appears/changes:
   switch to Isolated mode, clean up route files, regenerate `__canvas_preview__.tsx`
   as standalone entry. When file is deleted: switch back to App Shell mode.

2. `generator.ts` — add `generateStandaloneEntry()` that produces `__canvas_preview__.tsx`
   with `createRoot` and `PreviewWrapper` import.

3. `PreviewProxy._handleHttp()` — in Isolated mode: buffer the HTML response, find
   `<script type="module" src="...">` (filtering out `/@vite/`, `/@id/` scripts),
   replace src with `/src/__canvas_preview__.tsx`. Read `vite.config.ts` for `base`.
   On match failure: log warning, fall back to App Shell mode for this request.

**Verification**: create `.hyperide/preview.tsx` in `react-vite-tw4-twitter`, confirm
proxy swaps script tag (check network tab), confirm preview renders without app chrome.

---

### Step 5 — Isolated mode for Webpack (Extension, Tier 2)

**Target**: Webpack / CRA projects with `.hyperide/preview.tsx`.

**What to do**:

1. Detect entry file: look for `src/index.tsx`, `src/index.jsx`, `src/main.tsx` in order.
   Fallback: read `webpack.config.js` and parse the `entry` field.

2. `patchEntryFile(path)` — via `recast`: find the last `import` declaration in the AST,
   insert the `if (__preview) { import(...) } else { ... }` block after it,
   wrapping all non-import statements in the `else` branch.
   Tag inserted nodes with `/* @hyperide-managed */`.

3. `revertEntryFile(path)` — strip all nodes tagged `@hyperide-managed`. Run on
   deactivation or when wrapper file is deleted.

**Verification**: test with a CRA project, confirm entry file is patched cleanly,
confirm revert leaves no trace.

---

### Step 6 — SaaS cleanup

**Target**: remove preview routing from `client/main.tsx`, unify with Extension approach.

**What to do** (coordinate server + client deploy):

1. `client/main.tsx` — remove `isPreviewPath` check and `__canvas_preview__` import.

2. `client/CanvasPreviewEntry.tsx` — delete.

3. `server/routes/generatePreview.ts` — remove the HTTP endpoint entirely.

4. `client/components/IframeCanvas.tsx` — remove `POST /api/generate-preview` calls.
   Component switch triggers a WebSocket message that calls `ensureComponent()` directly
   on the server.

5. `server/proxy/project-preview.ts` — for containers without `.hyperide/preview.tsx`:
   add Tier 1 HTML rewrite (same logic as Extension). For containers with wrapper:
   pass through (the generated standalone entry handles it).

**Verification**: select a component in SaaS, confirm preview renders without the
`/api/generate-preview` network call appearing in devtools.
