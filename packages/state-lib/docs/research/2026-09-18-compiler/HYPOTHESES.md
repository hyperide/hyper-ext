## Promotion vector, not a single score

Correctness: zero known failing acceptance tests; identical observable values, ordering, errors, cancellation, identity, ownership and sync/async boundaries. Latency: every declared case and target, tiny/large, cold/warm, per-event p50/p95/p99 with page-level replicates; no geometric mean may hide a losing cell. Resources: raw/minified/gzip/Brotli transfer by route, peak/live heap, allocations, build latency and worker memory. Code: authored LOC/AST nodes/branches/casts/effects plus generated bytes reported separately. UX: caret/IME, focus, selection, keyboard, scroll, stale-response and aria-live correctness. Readability: blinded implementation/bug-fix tasks measuring completion time and error rate, not an assistant's aesthetic score.

The preview currently gates only metrics explicitly supplied by a trusted profile and actual emitted raw/gzip bytes. The broader vector above is a research/acceptance contract, not all implemented gates. Sub-microsecond zero samples caused by timer resolution cannot support universal superiority. Memory, power and physical-mobile results are still missing.

Build-time choices are valid only for their declared target/workload contract. A portable artifact must use the common supported path or explicit separately qualified build variants. Runtime capability branching is not silently inserted while claiming it was compiled away. If a property truly depends on a runtime workload, document that boundary or retain baseline rather than pretend static analysis knows it.
