### Algorithm portfolio: implementation and evidence are separate

**Audit date: 2026-09-23.** The earlier site did not contain a complete algorithm inventory. CHAMP, RRB, Perceus and snapshottable stores appeared in the separate hybrid research report, not in its public concept catalogue. Mentions of generic transients or vectors were not equivalent to tested implementations. This register closes the documentation gap; it does not claim that every candidate below has been implemented or measured.

The private-builder mechanism is informed by [Clojure transients](https://clojure.org/reference/transients), but post-publication handle invalidation is not silently substituted for the existing escaped-draft contract. [RRB vectors](https://clojure.github.io/core.rrb-vector/) target persistent sequence operations; they are not automatically faster than a short array. [Perceus](https://www.microsoft.com/en-us/research/publication/perceus-garbage-free-reference-counting-with-reuse/) relies on an explicit ownership analysis, not a guessed JavaScript reference count.

#### Admission and code-size balance

A candidate is admitted only when it preserves the declared semantic contract, improves the important cases and does not regress any required edge case. Compare the complete state operation and publication path, not only an inner loop. Retain cold startup, 0/1-item cases, long single arrays, dense and mixed batches, old-version branching, unknown callbacks, invalid input, rollback, subscribers and history in the matrix. A finite measured matrix is not a proof over every possible browser schedule.

Generated code has both relative and absolute budgets. Measure raw/minified, gzip and Brotli bytes for the **actual entry/route bundle**, include shared runtime imports and worker/Wasm artifacts, count duplicate specialization bodies and compare small/medium/large command catalogues. A fast specialization that breaches a hard budget is not admitted. A default relative fallback must not silently become a size exemption when the baseline itself exceeds the absolute project budget. Shared helpers, bounded unrolling and ordinary compact loops are candidates, not failures of compilation.

The optimization target is a constrained set of alternatives, not a weighted score that can hide a slow edge case or a giant bundle behind a fast median. Record both the current equivalent runtime baseline and the original application target. Keep a reference fallback when a proof or measurement is missing, but keep working on that path if it still fails the application target.

Marketing articles are separate from this technical record. They require a demonstrated achievement or discovery, a useful explanation of the mechanism and a clear user benefit. Current unfinished-work reports are withdrawn from the blog. Future illustrations must show actual values, changed versus shared memory, work avoided and execution/output differences—not three uninformative rectangles.
